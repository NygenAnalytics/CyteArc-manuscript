# Mapping

How accurately, quickly and in how much memory do queries map onto a finished CyteArc analysis used as a reference, compared with CellTypist, Seurat and R Symphony, on held-out blood, kidney and lung studies and on blood references of 0.5 to 4.29 million cells; what does annotating blood stores in place against the largest reference cost; how much time does reusing stored artifacts save when the neighbor count changes; and does CyteArc's Symphony correction match the R calculation?

Run: each Modal step is `uv run --group cloud python -m experiments.modal_runner run MODULE FUNCTION payload.json`, with `--image mapping` for CellTypist and `--image r_mapping` for Seurat and R Symphony. Payloads name their bucket locations as `s3://` URIs, and every recorded step takes a `recordUri`.

1. Held-out studies: `mapping.cross_study_mapping` `run` with `mode` `prepare` for each tissue, then with `mode` `benchmark` for each CyteArc arm (`referenceMethod` `unintegrated` or `integrated`); `mapping.comparators` `mapping_python_job` and `mapping_r_job` on the same prepared inputs; then `mapping.cross_study_mapping` `evaluate`. For the kidney and lung references' UMAPs, `mapping.cross_study_mapping` `reference_umap` with each tissue's `inputManifestUri` and `benchmarkRun`, the run block of its unintegrated benchmark's pipeline report: it rebuilds the reference with UMAP added, checks that the rebuild ran the benchmark's CyteArc version and configuration on the same cells, and saves the UMAP with each cell's labels; `uv run --locked python -m experiments.mapping.reference_umap_rasters held-out RESULT` on each job's result bins that UMAP by harmonized label.
2. Reference ladder: `mapping.cross_study_mapping` `run` with `mode` `prepare` and a `referenceLadder` design: reference studies AIDA, Yazar, COMBAT, the Stephenson COVID-19 atlas, Hao, JDM and arthritis; query studies Lee, Schulte-Schrepping and Ivanova; reference sizes of 500,000, 1,500,000 and 3,000,000 cells and the whole pool; 33,334 query cells per study; cell types expected to have at least 100 cells in the smallest reference; seed 4444. Then `run` with `mode` `benchmark` and the comparator functions for each `referencePart` and method, `mapping.cross_study_mapping` `evaluate_ladder`, and `uv run --locked python -m experiments.mapping.collect_records reference-ladder RECORD`, where RECORD is the `evaluate_ladder` job record. `uv run --locked python -m experiments.mapping.reference_umap_rasters ladder-reference CELLS_NPZ`, on a local copy of the `cells.npz` of reuse's cohort analysis, bins the ladder reference's cells in that analysis's Harmony UMAP by type.
3. Blood store annotation: `mapping.blood_store_annotation` `build_reference` once on the ladder's whole reference, then `map_and_aggregate` with each `study` of its `STUDIES`, and `uv run --locked python -m experiments.mapping.collect_records blood-store-annotation RECORD...` on their job records, which reads each store's `cells.npz` from the bucket, or from a folder named for the store beside a local copy of the job record.
4. Artifact reuse and embryo reference mapping: `mapping.mapping_reruns` `rerun_job` and `mapping_job` on the benchmark analysis stores; the neighbor-count fork ran `rerun_job` on the store of `embryo_rna_scaling_10000000_cells_replicate_4` with the stored run's resources (16 workers and a 48 GiB budget on 16 CPUs and 64 GiB, `cpu` and `memoryMb` in the payload) and its parallel settings (`annParallel` and `umapParallel` true), collected with `uv run --locked python -m experiments.mapping.collect_reruns embryo_rna_scaling_10000000_cells_replicate_4`. A fork reuses any artifact the store already holds with the same parameters, whatever its thread counts, so it runs on a store no earlier fork has written to.
5. Symphony check: `mapping.hlca` `run` with `mode` `mapping`, then with `mode` `rSymphony` and the `--image r_mapping`.
6. Kang PBMCs: `runtime.method_checks` `run` with a payload naming `mapping.mapping_kang`, `mapping.mapping_reads` or `mapping.symphony_fixture`.

Then `uv run --locked python -m experiments.mapping.reference_ladder_summary` writes accuracy, macro F1, donor-bootstrap intervals, rare-type means and step times of the ladder, `experiments.mapping.blood_store_annotation_summary` the annotation's totals, its range of store mapping seconds and its label agreement over the typed cells, `experiments.mapping.held_out_summary` each method's disagreement on the held-out kidney and lung studies and the bytes Seurat and R Symphony save to reuse each held-out reference, and `experiments.mapping.neighbor_count_fork_summary` the minutes the neighbor-count fork of a stored embryo analysis recomputed and looked up against the stored analysis, all to `.build/derived/mapping/`.

Needs: `benchmarks`, whose embryo analysis stores `mapping.mapping_reruns` uses as references, and `reuse`, whose exported H5AD files of the ten blood studies (AIDA, Yazar, COMBAT, the Stephenson COVID-19 atlas, Hao, JDM, arthritis, Lee, Schulte-Schrepping and Ivanova) the ladder samples and whose cohort analysis's Harmony UMAP the ladder reference's raster bins; the CyteBase stores of Gong, Perez, Ren, Sound Life, van der Wijst, Wells and Yoshida on Hugging Face; the core Human Lung Cell Atlas and the blood, kidney and lung studies from CELLxGENE; and the Kang PBMCs. Jobs and collection read the experiment bucket through `R2_ENDPOINT_URL`, `R2_BUCKET`, `R2_ACCESS_KEY_ID` and `R2_SECRET_ACCESS_KEY`, and the Kang checks use `CYTEARC_DOWNLOADS` and `CYTEARC_RUNS`.

Records:

- `reference_ladder.json`: for each reference size and method, the outcome, container memory and peak, persisted reference bytes, seconds per step group and per-donor confusion counts, with the ladder design.
- `blood_store_annotation/<study>.json`: for each annotation job, the reference opening and reads, the container peak, and each store's cells, donors, missing reference genes and mapping seconds, with its cells whose author label is one of the reference's types and those whose transferred label agrees, counted from the per-cell labels the job uploaded.
- `cross_study/`: the held-out mapping runs of each tissue and method with their per-cell predictions, and `evaluation.json`, their accuracy and cost.
- `held_out_reference_umap/kidney.npz` and `lung.npz`: each held-out reference's UMAP binned by harmonized label on a square grid of 300 by 300, with `kidney.json` and `lung.json`, its cells, its cells per label and the rebuild's checks against the benchmark.
- `ladder_reference_umap_raster.npz`: the ladder reference's cells in the Harmony UMAP of reuse's cohort analysis, binned by type on a square grid of 420 by 420, with `ladder_reference_umap_raster.json`, the reference studies and the cells per type and per study.
- `artifact_reuse_runs.json`: the neighbor-count fork on the ten-million-cell embryo analysis store.
- `symphony.json`: CyteArc's Symphony soft assignment and query correction against R Symphony 0.1.3.
- `kang_stimulated_query_mapping.json`, `kang_mapping_coverage.csv`, `kang_mapping_label_accuracy.csv` and `kang_reference_read_requests.json`: stimulated Kang PBMCs mapped onto control PBMCs, with the reference reads of each step.
