# Catalogue

What does the CyteBase release hold, from stores and observations to object sizes, which human tissues and diseases does it cover across several studies, and what does screening an interferon gene panel in place across all of its human blood stores take in time, data and memory, and which diseases raise their donors' interferon response above the healthy donors of the same store?

Run, in order:

1. Catalogue: `uv run --locked python -m experiments.catalogue.cytebase_catalog --selection collections.json` downloads the release catalogue, checks it against its published SHA-256 and writes `records/cytebase_catalogue.json`; `collections.json` is the CyteBase build's selection of CELLxGENE collections, from which the record's build counts come.
2. Object sizes: `uv run --locked python -m experiments.catalogue.cytebase_catalog --list-objects` lists every object of the release, then `uv run --locked python -m experiments.catalogue.catalogue_objects` writes `records/catalogue_objects.json`.
3. Cohort discovery: `uv run --locked python -m experiments.catalogue.cohort_discovery` with `--dataset` for each of the 11 stores that `records/cohort_discovery.json` lists under `cohortMetadata.datasets`, in that order; then with `--count-bytes hf://buckets/Nygen/cytebase/cytearc_docs/tabula_sapiens/data.zarr`.
4. Atlas thumbnails: `uv run --locked python -m experiments.catalogue.overview_embeddings`.
5. Blood store screen, two jobs: `uv run --group cloud python -m experiments.modal_runner run catalogue.catalogue_screen run payload.json --cpu 8 --memory-gib 32 --secret SECRET`, with payload `storeSet` `other_blood_stores`, `storeConcurrency` 4, `nthreads` 8 and `memBudget` `3G`, then the same with `storeSet` `immune_cohorts` and `requireToken` true. The secret holds the bucket credentials; for the `immune_cohorts` job it also sets `HF_TOKEN`, and the `other_blood_stores` job reads the stores without a token. Each payload names `r2EndpointUrl`, the bucket's endpoint, and `recordUri`, the `s3://` URI in the bucket where the runner saves the run record. Then `uv run --locked python -m experiments.catalogue.catalogue_screen collect RECORD_URI RECORD_URI` on the two run records writes `records/blood_store_screen.json`, and `uv run --locked python -m experiments.catalogue.catalogue_screen keep RECORD_URI --screen blood_store_screen` on each writes the job's record and its donor table, which the job uploads under the payload's `outputPrefix`, into `records/blood_store_screen/`. These two jobs ran an earlier form of the screen: each payload listed its stores under `storeIds`, the panel held six interferon genes, no sample rule applied and each donor's samples were pooled.
6. Interferon screen: the same two jobs, both with `requireToken` true, in the form `catalogue_screen.run` has here: it applies the blood sample rules of `runtime.blood_samples`, scores the 18 interferon genes of `INTERFERON_GENES` for each donor, sample and coarse cell type, and z-scores them against the store's healthy donors; `uv run --locked python -m experiments.catalogue.catalogue_screen keep RECORD_URI --screen interferon_screen` on each run record writes `records/interferon_screen/`.
7. Summaries: `uv run --locked python -m experiments.catalogue.catalogue_objects_summary` and `experiments.catalogue.blood_store_screen_summary` write the release totals by object kind and the screen's totals over both jobs to `.build/derived/catalogue/`.

Needs: `benchmarks`, whose embryo and mouse brain analysis stores `catalogue.overview_embeddings` reads; CyteBase release 2610 on Hugging Face (its catalogue, object listing and stores) and the `cytearc_docs` Tabula Sapiens store; the variables `CYTEARC_DOWNLOADS`, `R2_ENDPOINT_URL`, `R2_BUCKET`, `R2_ACCESS_KEY_ID` and `R2_SECRET_ACCESS_KEY` that `experiments/README.md` describes.

Records in `records/`:

- `cytebase_catalogue.json`: stores, collections, observations, organisms, tissues, diseases and cell types of the release, and the CELLxGENE datasets left out.
- `catalogue_objects.json`: for each store, its cells, genes, estimated nonzero counts, bytes and objects by kind and the size of each count shard.
- `cohort_discovery.json`: human diseases studied in at least three collections, tissues with several studies, large multimodal stores, and the cell metadata of 11 blood stores compared in pairs.
- `tabula_count_bytes.json`: the bytes and objects of both count arrays of the Tabula Sapiens store that the remote queries read.
- `atlas_embedding_thumbnails.json` and `.npz`: UMAP thumbnails of the one-million-cell embryo and 1.3-million-cell mouse brain analyses.
- `blood_store_screen.json`: the gene panel and, for each job, its stores, settings and placement, cells read, donors scored, wall seconds, rate-limit waits, HTTP requests and bytes, the stores' count bytes and the container's memory peak and limit.
- `blood_store_screen/` and `interferon_screen/`: each job's run record under its store set, `immune_cohorts.json` and `other_blood_stores.json`, with each store's cells, count bytes, HTTP requests, bytes received and seconds and the scores summarized by disease, and the job's donor table, `<store set>_donors.csv.gz`: one row per store, donor, disease label and coarse cell type (and sample, in the interferon screen) with its cells, the panel genes' counts and its interferon score.
