# Benchmarks

How long does a complete RNA workflow take with CyteArc and how much memory does it use, from 10,000 embryo cells to the 95,624,334 cells of Tahoe-100M; how many ranged reads does each count layout issue per pass; do count-matrix steps stay within the memory budget; and how does CyteArc compare with Scanpy, Seurat, BPCells and Census on six atlases in time, memory and cluster agreement?

Run each job with `uv run --group cloud python -m experiments.modal_runner run MODULE FUNCTION payload.json --region us`. Payloads name bucket locations as `s3://` URIs, and a `configPath` names a file in `configs/benchmark/`.

1. Inputs: `benchmarks.datasets` `prepare` (with `--image scanpy`, as it imports anndata) with `targetRows` 10,000, 100,000, 500,000, 1,000,000, 5,000,000 and 10,000,000, `samplingSeed` 0 and `datasetPrefixUri` naming `experiments/datasets/embryo` samples the mouse embryo atlas; `benchmarks.scanpy` `brain_prepare_job` prepares the mouse brain, and `benchmarks.workflows` `prepare_job` Tabula Sapiens, the brain-atlas neurons and the prefrontal cortex cohort.
2. Embryo scaling series and storage arms: `benchmarks.scaling` `run` with replicates 4 to 6 of each `embryo_rna_scaling_*` configuration from 100,000 cells up and of `embryo_rna_memory_24_gib_8_workers` (object storage) and `embryo_rna_1000000_cells_local_disk`, then `uv run --locked python -m experiments.benchmarks.collect_benchmarks`, which collects both into `$CYTEARC_RUNS/benchmarks/results/`, from where they move into `records/`, and `store_sizes`, `layout_geometry` and `planner_admission` the same way. The resource trace repeats the ten-million-cell replicate 1 under its own run tag: `benchmarks.scaling` `run` with `configPath` `embryo_rna_scaling_10000000_cells_resource_trace_replicate_1.toml` and `resourceTrace` true, then `uv run --locked python -m experiments.benchmarks.collect_resource_trace experiments/benchmarks/configs/benchmark/embryo_rna_scaling_10000000_cells_resource_trace_replicate_1.toml`.
3. Workflows and toolkits: `benchmarks.workflows` with the job that `TOOLS_BY_NAME` gives each tool, three replicates per dataset, starting at 32 GiB and moving comparators up to 64, 128, 256 and 336 GiB when they run out of memory. The CyteArc arms are `cytearc` and `cytearc_matched`; the budget sweep runs `cytearc_limit4`, `cytearc_limit8`, `cytearc_limit16` and `cytearc` with `stopAfter` `runPca`, and the 4 GiB count policy was screened with 125 MB and 250 MB units. Then `benchmarks.cluster_quality` `quality_job` with `metrics` `embedding_and_clustering` compares the kept outputs on `embryo_1000000` and `brain_1306127`. Collect with `uv run --locked python -m experiments.benchmarks.collect_workflow_runs`, `collect_tool_runs --run-tag toolkit_comparison --cytearc-tag cytearc_rna_workflow` and `collect_quality`. CyteArc's marker-only runs (`markers_cytearc`, replicates 1 to 3 on `embryo_1000000`, `brain_1306127` and `tabula_sapiens`) were rerun with `cytearc_tool_job` on 8 CPUs and 32 GiB, non-preemptible, under the run tag `cytearc_marker_statistics`, on the common inputs that `markers_prepare_job` writes, once each was checked to equal the comparators' input in SHA-256 and bytes; `uv run --locked python -m experiments.benchmarks.collect_tool_runs --run-tag cytearc_marker_statistics --replace-in experiments/benchmarks/records/toolkit_comparison_runs.json` puts them in place of their earlier records, keeps every other record, and writes the first replicates' sampled statistics into `records/raw/`. The native BPCells runs (`bpcells_cached` and `bpcells_cached_spca`, every replicate the comparison reports) were rerun with `r_tool_job` on their original inputs, CPUs and memory, non-preemptible, under the run tag `toolkit_comparison_bpcells_threaded`, and `uv run --locked python -m experiments.benchmarks.collect_tool_runs --run-tag toolkit_comparison_bpcells_threaded --replace-in experiments/benchmarks/records/toolkit_comparison_runs.json experiments/benchmarks/records/toolkit_comparison_replicate_runs.json` puts each in place of its record in whichever file holds it; `quality_job` then compares the kept outputs of their first replicates.
4. Count layouts: `benchmarks.count_requests` `prepare` at 5,000,000 and 10,000,000 cells, `run` for each layout (`fixed`, `scaled`) and replicate 1 to 3 on 8 CPUs and 64 GiB, and `compare` on the twelve run records; then `uv run --locked python -m experiments.benchmarks.count_requests`.
5. Memory budget: `benchmarks.scaling` `run` with `embryo_rna_cluster_labels_10000000_cells.toml` makes the Leiden labels that the imported-labels job reads. Then `benchmarks.budget_compliance` `run` with `configPath`, `arms` and `containerMemoryMb` for each configuration in `budget_compliance.COLLECTED`, with the arms named there, on 8 CPUs and 32 GiB at 1,000,000 cells or 48 GiB at 10,000,000 cells; then `uv run --locked python -m experiments.benchmarks.budget_compliance collect`.
6. Tahoe-100M: `benchmarks.tahoe` `stage` with `start` and `stop` covering the 3,388 Parquet files of revision `2dc57900b7981cfcf5e211527169a0b006546a95`; `benchmarks.scaling` `stage` with each stage of `tahoe_rna_6011925_cells_scaled_layout_replicate_1.toml`, `tahoe_rna_95624334_cells_scaled_layout_replicate_1.toml` to `_replicate_3.toml` and `tahoe_rna_95624334_cells_fixed_layout_replicate_1.toml`, each stage in its own call; `benchmarks.tahoe` `export` with the first full scaled configuration and `layoutConfigPath` naming the fixed one; then `uv run --locked python -m experiments.benchmarks.collect_tahoe`. BPCells on Tahoe-100M is one `benchmarks.workflows` `r_tool_job` call with tool `bpcells_cached_spca`, `inputMode` `directory` on the staged revision and `datasetFiles` naming its gene table, data files and their staging records, run with `--image r_multimodal`, 16 CPUs, 336 GiB and 2,560 GiB of disk; the R workflow first writes the Parquet files as H5AD shards (`convertParquet`, timed as preparation). Collect it with `collect_tool_runs --run-tag toolkit_comparison_tahoe_threaded_pca --destination experiments/benchmarks/results/toolkit_comparison_tahoe_runs.json`, from where it moves into `records/`.

The `benchmarks` modules in the `Makefile`'s `source-data` target turn the records into summaries in `.build/derived/benchmarks/`.

Needs: no other experiment; the mouse embryo atlas, Tabula Sapiens, the Human Brain Cell Atlas neurons and the PsychAD prefrontal cortex cohort from CELLxGENE; the 10x Genomics 1.3-million-cell mouse brain, as the `tenx_1.3M_brain_rnaseq` store of CyteArc's documentation datasets; and Tahoe-100M from Hugging Face; the bucket variables and `CYTEARC_RUNS` that `experiments/README.md` lists.

Records:

- `rna_workflow_runs.json`: the CyteArc workflow on six datasets, three replicates per arm, with stage times and memory peaks, and the preparation record of each input.
- `toolkit_comparison_runs.json`: Scanpy, Scanpy with Dask, Seurat, Seurat with BPCells, BPCells and Census on the same inputs, every memory tier attempted, with the marker inputs and checks (CyteArc's marker-only runs are the reruns of step 3, without memory tiers); `raw/marker_statistics_*.csv` holds the sampled marker statistics of each tool's first replicate, and `raw/prefrontal_cortex_seurat_bpcells_scaled_pca_interruption.json` the first attempt of Seurat with BPCells on the prefrontal cortex cohort.
- `toolkit_comparison_brain_dask_runs.json`: Scanpy with Dask on the mouse brain, three replicates at 128 GiB, run after the comparison was collected and collected alone with `collect_tool_runs --run-tag <tag> --destination <file>`; `tool_summary` adds its runs to the comparison's under the comparison's tool name, `scanpy_dask_covariance_csc`.
- `toolkit_comparison_tahoe_runs.json`: native BPCells on Tahoe-100M, one run on 16 CPUs and 336 GiB that ran out of memory in Leiden clustering after 17.4 hours.
- `toolkit_comparison_replicate_runs.json`: further replicates of comparison arms that had fewer than three completed runs at the memory where the tool completed (Scanpy and Seurat with BPCells on the mouse brain, Seurat with BPCells on the 2.5M-cell neurons, BPCells and Scanpy with Dask on the 4.1M-cell cohort, Scanpy reading 1M embryo cells from Census, BPCells on the 10M-cell embryo sample), collected alone the same way; `tool_summary` adds them to the comparison.
- `cluster_quality.json`: cluster and principal-subspace agreement between the CyteArc, BPCells and Scanpy runs on the cells they all keep, and against author labels.
- `memory_preprocessing.json`: input conversion through PCA under 4, 8, 16 and 24 GiB, three replicates each, and the two 4 GiB count policies screened.
- `memory_budget_stages.csv`: one row per job, arm and step of the 8 GiB runs at 1,000,000 and 10,000,000 cells: seconds, container peaks from the worker's and the parent's sampler, planned reservation, and for a step that refused its budget, the cells, memory estimate and graph edges of its message.
- `memory_read_admission.json`: the planner's read plan for every orientation, size, budget and core count tested.
- `count_layout_geometry.json` and `.csv`: the paired count layout at each embryo size.
- `analysis_store_sizes.json`: bytes by component of each embryo analysis store.
- `count_requests.json`: the fixed and scaled layouts at 5,000,000 and 10,000,000 cells, three runs each, with requests, bytes and seconds of each count pass on frozen inputs, and their paired validation.
- `raw/rna_scaling_runs.json`, `rna_scaling_stage_measurements.csv` and `rna_scaling_execution_reports.csv`: the embryo scaling series from 100,000 to 10,000,000 cells, three runs per size.
- `raw/rna_resource_runs.json` and `rna_storage_backend_runs.json`: CyteArc on the one-million-cell embryo from object storage and from local disk, and local and remote Dask storage.
- `raw/tahoe_rna_stage_measurements.json`: each stage of the Tahoe-100M pilot, the three replicates of the full run and the fixed-layout run: status, seconds, container peak, resources, placement, range reads and band geometry.
- `tahoe_rna_scaling_results.json`: the Tahoe-100M atlas, the full run's stages against the pilot, preparation and analysis hours, each replicate's hours and stage times and peaks, clusters and cell lines, and the fixed against the scaled layout.
- `tahoe_umap_raster.npz`: the full run's UMAP as a 2,048 by 2,048 grid of cell counts and commonest cell line.
- `tahoe_cluster_cell_lines.csv`: the full run's cells per Leiden cluster and cell line, from its export.
- `tahoe_cell_lines.csv`: the full run's cell lines in the order the UMAP raster codes them, each with its Cellosaurus ID, name and organ from Tahoe-100M's `metadata/cell_line_metadata.parquet`.
- `resource_trace_10000000_cells/`: the ten-million-cell run's container memory, CPU seconds and network bytes received once a second with the stage running (`resourceTrace.json`), and the memory budget and CPU limit of each stage (`resources.json`).
